## 一、核心原则

-   注释解释"为什么"，不解释"是什么"。
-   公共 API 必须有文档注释。 类、接口、公共方法/函数、导出符号均须注释。
-   注释与代码必须同步。修改代码时必须同步更新注释。
-   废弃代码要删除，而不是注释。
-   宁用中文也不用半吊子英文。专有名词保持英文原文。


## 二、必须写注释的场景

-   复杂业务逻辑。如：先扣库存再下单，防止超卖
-   并发/线程安全。如：此处必须加锁，多线程下 balance 存在竞态条件
-   非直觉的性能优化。如：用 dict 替代 list 查找，O(n) → O(1)
-   外部系统的坑。如：微信支付回调可能重复推送，需做幂等处理
-   魔法数字/常量。如：MAX_RETRY = 3 支付网关建议重试上限
-   枚举值。如：每个枚举项必须注释说明用途
-   重要分支判断。如：说明走到此分支的条件和原因


## 三、禁止写注释的场景

-   `i += 1  # i 自增 1`。翻译式/鹦鹉注释，无信息量
-   `Added by zhangsan 2024-03-01`。这是 git blame 的职责
-   注释中包含密码、密钥、内部 IP。安全隐患
-   大段注释掉的代码


## 四、TODO / FIXME 规范

-   **TODO** — 目前能工作，将来需要优化完善
-   **FIXME** — 已知有缺陷，需要尽快修复

格式：

```
TODO(负责人 YYYY-MM-DD): 描述 [可选: issue编号]
FIXME(负责人 YYYY-MM-DD): 描述 [可选: issue编号]
```

示例

```
TODO(fenglepeng 2026-05-01): 迁移到新鉴权 SDK 后移除
FIXME(fenglepeng 2026-04-15): 高并发下存在 race
```


## 五、各语言注释风格

### Python（PEP 257 + Google Style）

```python
class OrderService:
    """订单服务，处理下单、退款、查询等核心流程。
    
    Attributes:
        db: 数据库连接实例。
        cache: 缓存客户端。
    """
    
    def create_order(self, user_id: int, items: list[dict]) -> Order:
        """创建订单并扣减库存。
    
        采用先扣库存后创建订单的策略，失败时通过 Saga补偿回滚。
        详见: https://wiki.internal/order-saga
    
        Args:
            user_id: 用户 ID。
            items: 商品列表，每项包含 sku_id 和 quantity。
    
        Returns:
            创建成功的 Order 对象。
    
        Raises:
  I         nsufficientStockError: 库存不足时抛出。
        """
```

要点：
- 公共模块、类、函数必须写 docstring（Google 风格：Args / Returns / Raises）         
- 私有函数 docstring 可选，签名不清晰时才写
- 行内注释 # 后空一格，与代码间隔至少两个空格

### Shell（Google Shell Style Guide）

```shell
#!/bin/bash  
#  
# 每日凌晨清理 30 天前的临时文件。         
# Cron: 0 3 * * *      
 
#######################################         
# 清理备份目录中的过期文件。     
# Globals:   
#   BACKUP_DIR         
# Arguments: 
#   无       
# Outputs:        
#   清理状态输出到 stdout        
# Returns:        
#   0 成功，非 0 失败  
#######################################    
function cleanup() {   
    # 保留 30 天是因为月报生成周期最长 28 天         
    local retention_days=30      
    find "${BACKUP_DIR}" -mtime +"${retention_days}" -delete
}
```

要点：       
- 文件头必须有脚本说明 
- 函数必须有注释：Globals / Arguments / Outputs / Returns 
- TODO 格式：# TODO(username): description

### SQL     

```sql
-- ============================================================
-- 创建用户表
-- 作者：fenglepeng    
-- 日期：2026-04-10    
-- ============================================================
 
CREATE TABLE users (   
    idBIGINT    UNSIGNED      NOT NULL AUTO_INCREMENT COMMENT '用户唯一标识',       
    email       VARCHAR(255)  NOT NULL COMMENT '注册邮箱，全局唯一',  
    status      TINYINT       NOT NULL DEFAULT 1 COMMENT '1-正常 2-禁用 3-注销', 
    created_at  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间', 
    PRIMARY KEY (id),  
    UNIQUE KEY uk_email (email)       
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户基础信息表';   
        
-- 取最近 7 天活跃用户，排除测试账号（uid < 1000）
-- 索引命中: idx_user_login_time 
SELECT uid, login_time  
  FROM user_login        
  WHERE login_time >= DATE_SUB(NOW(), INTERVAL 7 DAY)       
  AND uid >= 1000;      -- 测试账号 uid 统一分配在 1000 以下    
```

要点：       
- 表和列必须用 COMMENT 写入数据字典        
- 复杂查询前写概要注释，说明业务意图和命中索引       
- 使用 -- 注释（SQL 标准），避免 MySQL 特有的 #      
      

### YAML / 配置文件        

```yaml
# ============================================================ 
# 应用配置 - 生产环境  
# 注意：敏感信息通过环境变量注入，不要直接写入       
# ============================================================ 
 
server:      
  port: 8080    # 监听端口，LB 转发到此端口
  workers: 4    # 建议设为 CPU 核心数      
 
database:         
  host: ${DB_HOST}        # 从环境变量注入 
  password: ${DB_PASS}    # 绝对不要硬编码 
  pool:      
    max_open: 50# 根据数据库 max_connections 调整    
    max_lifetime: 300s    # 应小于数据库 wait_timeout
```

要点：       
- 文件头说明用途和适用环境       
- 每个非自明的配置项旁边说明含义、取值范围 
- 敏感字段标注来源（环境变量/密钥管理工具）
 

## 六、格式规范        

- 注释符后空一格 — `# 正确，#错误；// 正确，//错误`
- 行内注释间隔 — `代码与 # / // 之间至少两个空格`
- 注释位置 — `方法内部注释独占一行，不追加在语句后面`
- 对齐 — `仅连续 3 行以上末尾注释时做对齐`
- 语言统一 — `团队选定中文或英文，不混用`
- 标点 — `中文注释用中文标点，英文注释用英文标点`
- 末尾 — `注释后不留尾部空格`
