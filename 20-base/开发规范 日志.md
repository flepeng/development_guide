
## 基本原则

*   安全性：不输出机密、敏感信息，如用户个人信息、token等。
*   稳定性：不影响系统正常运行，修改日志打印逻辑时需要评审对性能、稳定性带来的风险。
*   有效性：避免打印无效、冗余的内容。
*   独立性：业务日志与系统日志需记录在不同的文件中。


## 打印时机

*   系统启动时：记录启动参数，核心模块或组件初始化的关键配置，以及启动完成的服务状态描述信息。
*   系统异常时：记录错误信息。
*   业务异常时：记录业务流程分支，包括请求参数不正确，第三方服务调用异常等。
*   关键动作时：记录核心角色触发的业务动作，如故障定位、审计。
*   远程调用时：记录对三方服务的调用，建议打印关键请求和响应参数。


## 日志级别

*   TRACE：最细粒度的日志，记录程序执行的每一步。开发环境使用
    
*   DEBUG：详细的调试信息，用于开发和测试阶段的问题诊断。生产环境默认关闭，仅在排查问题时动态开启。包括：
    *   方法入参/出参的完整内容
    *   中间计算过程、变量值、条件分支的判断结果
    *   SQL 语句及绑定参数、返回行数、耗时
    *   缓存 key、命中/未命中、过期时间
    *   算法/规则引擎执行过程、输入数据、每步计算结果、最终输出
    *   第三方调用的详细过程、请求/响应完整报文

*   INFO：记录系统正常运行中的关键事件，用于还原业务流程和排查问题。生产环境使用。包括：
    *   启动/停止时的服务名、版本号、生效的关键配置项、启动耗时
    *   请求入口，HTTP 方法、路径、核心入参（脱敏）、响应码、耗时
    *   关键业务状态变更业务实体 ID、前状态、后状态、操作人
    *   定时任务开始/结束，任务名称、处理总量、成功/失败数、总耗时
    *   消息生产与消费，topic、msgId、关键业务字段
    *   配置变更、缓存刷新等运维事件，变更项、旧值/新值、操作来源

*   WARN：潜在问题或非预期状态，当前功能未受损，但需要关注。生产环境使用。包括：
    *   接口响应时间超过阈值但未超时。接口名、实际耗时、阈值
    *   重试后成功。操作名、重试次数、每次失败原因摘要
    *   降级/熔断被触发。触发的规则名称、当前指标值、降级策略
    *   配置项使用了默认值（用户未配置）。配置项 key、使用的默认值 
    *   资源使用率接近上限（连接池 >80%、磁盘 >85%），资源名称、当前值、阈值
    *   数据格式不规范但仍可解析。 数据来源、原始值摘要、解析结果
    *   业务校验失败（参数非法、权限不足等用户侧原因），userId、校验规则、失败字段及值
    *   即将废弃的。API 被调用被调用的 API 路径、建议替代的新API、计划下线日期

*   ERROR：运行时错误，当前请求/操作失败，但不影响系统整体运行。生产环境使用。包括
    *   未捕获的业务异常。请求入参（脱敏）、异常类型、完整堆栈
    *   外部服务调用失败（5xx/超时），重试耗尽。 目标地址、请求参数、响应码、重试次数、耗时、异常堆栈
    *   数据库操作失败（死锁、唯一键冲突等非预期）。SQL 摘要、绑定参数、异常堆栈
    *   消息消费失败进入死信队列。topic、msgId、消费次数、失败原因、异常堆栈
    *   定时任务执行失败。任务名称、触发时间、已处理数量、失败原因、异常堆栈
    *   资源耗尽（线程池满、连接池满）。 资源名称、当前值/最大值、等待队列长度、异常堆栈

*   FATAL：导致应用程序无法继续运行的严重错误。生产环境使用。包括
    *   系统启动失败（端口占用、关键配置缺失、数据库连接池初始化失败）。失败原因、配置项名称/值、异常堆栈
    *   核心依赖完全不可用且无降级方案。依赖服务地址、错误码、已重试次数、异常堆栈
    *   数据损坏导致无法恢复。损坏数据的标识、影响范围、异常堆栈
    *   OOM 等 JVM/运行时 致命错误。当前内存使用情况、触发点、异常堆栈


## 注意事项

*   记录关键参数和状态信息：如输入参数、输出结果、关键数据状态等，有助于还原问题现场和分析异常触发的条件。
*   记录重要操作：对于涉及重要数据变更或关键业务流程的操作，记录操作前后的数据状态、操作人信息以及关键动作，以便进行数据追踪、审计和故障分析。
*   记录重要配置变更：如接口调用开关、切量开关等配置，有助于追踪配置变更对系统稳定性和性能的影响，以及在配置错误引起的异常情况时进行故障排查。
*   记录日志归档和存储策略：确保日志文件不会无限增长，影响系统性能甚至磁盘写满。
*   记录日志级别动态降级：在流量高峰前调整日志级别或关闭某些详细日志，以减少对系统性能的影响。


## 日志格式

简单

```
时间-线程id-级别-日志
```

复杂

```
参考：固定前缀 - 调用类型 - 自定义前缀 - 自定义信息

其中：
    固定前端：包含时间、级别（TRACE、DEBUG、INFO、WARN、ERROR）、版本（V1、V2、V3）、RequestId、应用ID、应用环境（test、pre、pro）
    调用类型：包括HTTP、RPC、DAL、CAL、MQ

分割：
    内部各字段以"|"分割
    模块之间使用" - "(空格+中划线+空格)分割

示例：
[2026-01-01 01:01:01.001]|INFO|V1|xxx|1xxx|应用demo|test - HTTP(http://127.0.0.1:80/aaa/bbb,GET) - xxx - xxx
```
